# Как подключить Ahrefs к Claude Code через MCP

Инструкция проверена на macOS 13 августа 2026. Всё, что здесь написано, реально
выполнялось — включая две ловушки в конце, на которых мы застряли.

После подключения Claude сможет сам ходить в Ahrefs: снимать трафик, ключи,
ссылочное, делать Batch Analysis — без ручных выгрузок CSV.

---

## Что нужно

- **Подписка Ahrefs — Lite или выше.** Отдельный API-доступ покупать не надо,
  MCP входит в обычную подписку. На Lite ответ обрезается до 100 строк на запрос,
  на Enterprise лимита нет.
- **Claude Code**, установленный локально.
- Каждый вызов расходует те же API-юниты, что и обычный API Ahrefs. Для
  ориентира: весь наш прогон из двенадцати отчётов съел ~19 тыс. юнитов из 2 млн.

---

## Четыре шага

### 1. Добавить сервер

В терминале, из папки проекта:

```bash
claude mcp add --transport http ahrefs https://api.ahrefs.com/mcp/mcp
```

Сервер хостится у Ahrefs, локально ничего ставить не нужно. Команда просто
записывает адрес в конфиг проекта — доступа к аккаунту она сама по себе не даёт.

### 2. Авторизоваться

```bash
claude mcp login ahrefs
```

Откроется браузер, залогинишься в Ahrefs и подтвердишь доступ. Команда сама
поймает редирект и сохранит токен — дальше он переиспользуется.

### 3. Перезапустить сессию Claude Code

**Обязательно.** Список MCP-инструментов формируется при старте сессии, поэтому
уже запущенная сессия сервер не увидит.

### 4. Проверить

```bash
claude mcp get ahrefs
```

Должно быть:

```
Status: ✔ Connected
```

Всё, готово.

## Две ловушки, на которых легко застрять

**`/mcp` внутри чата пишет «No MCP servers are configured», хотя вы только что
добавили сервер.** Это не ошибка: сессия прочитала конфиг при старте, когда
сервера ещё не было. Лечится перезапуском. То же самое произойдёт и после шага 2:
если авторизоваться, не перезапустив сессию, инструменты не появятся, даже когда
`claude mcp get` уже показывает `Connected`. Проще сразу сделать оба шага, а
перезапуститься один раз в конце.

**В расширении VSCode интерактивное меню `/mcp` может не отрисоваться** — вместо
него будет строчка «Use /mcp in the terminal for details», и авторизоваться
оттуда не получится. Поэтому в инструкции и стоит `claude mcp login` — она делает
то же самое из обычного терминала и от интерактивного меню не зависит.

## Если что-то пошло не так

Посмотреть состояние всех серверов:

```bash
claude mcp list
```

`! Needs authentication` — значит шаг 2 не прошёл, повторите `claude mcp login ahrefs`.

Проверить, что эндпоинт вообще жив:

```bash
curl -s -o /dev/null -w "%{http_code}\n" -X POST \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"probe","version":"1"}}}' \
  https://api.ahrefs.com/mcp/mcp
```

**`401` — это нормально и правильно:** сервер жив и требует авторизации. Проблема
не в нём.

Сбросить авторизацию и пройти заново:

```bash
claude mcp logout ahrefs
claude mcp login ahrefs
```

Удалить сервер совсем:

```bash
claude mcp remove ahrefs -s local
```

## Что делать после подключения

В нашем проекте готовый список выгрузок лежит в
[`BRAINSTORM-result.md`, раздел 7-бис](BRAINSTORM-result.md) — что брать, в каком
приоритете и в каком режиме. Достаточно сказать Claude:

> забери из Ahrefs выгрузки по списку из раздела 7-бис в `BRAINSTORM-result.md`

Две вещи, которые стоит знать заранее, иначе выгрузки получатся бесполезными:

**Апекс брать без поддоменов** — режим `mostbet.com/*`, не `*.mostbet.com/*`.
Иначе трафик `guidebook` усреднится с падением апекса, и понять, что именно упало,
будет нельзя.

**Три домена сетки — не сайты, а редиректы**, и Ahrefs покажет по ним пустоту.
Смотреть надо цели: `mostkupon.tr` → `mostbettr.asia`, `mostbetaz.biz` →
`mostbetazerbaycangiris.net`, `mostbett.com.kz` → `mostbetkazinokazakhstan.com`.

Результаты нашего прогона — в [`ahrefs/`](ahrefs/), разбор — в
[`ahrefs/README.md`](ahrefs/README.md).
