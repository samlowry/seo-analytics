# Как подключить Ahrefs к Claude Code через MCP

Инструкция проверена на macOS, август 2026. Всё, что здесь написано, реально
выполнялось — включая две ловушки в конце, на которых легко застрять.

После подключения Claude сможет сам ходить в Ahrefs: снимать трафик, ключи,
позиции, ссылочный профиль, делать Batch Analysis — без ручных выгрузок CSV.

---

## Что нужно

- **Подписка Ahrefs — Lite или выше.** Отдельный API-доступ покупать не надо, MCP
  входит в обычную подписку. На Lite ответ обрезается до 100 строк на запрос, на
  Enterprise лимита нет.
- **Claude Code**, установленный локально.
- Каждый вызов расходует те же API-юниты, что и обычный API Ahrefs. Для
  ориентира: дюжина разноплановых отчётов — примерно 19 тыс. юнитов.

---

## Четыре шага

### 1. Добавить сервер

В терминале, из папки проекта:

```bash
claude mcp add --transport http ahrefs https://api.ahrefs.com/mcp/mcp
```

Сервер хостится у Ahrefs, локально ставить нечего. Команда просто записывает
адрес в конфиг проекта — доступа к аккаунту она сама по себе не даёт.

Если нужен доступ во всех проектах, а не только в текущем, добавьте `-s user`.

### 2. Авторизоваться

```bash
claude mcp login ahrefs
```

Откроется браузер, залогинитесь в Ahrefs и подтвердите доступ. Команда сама
поймает редирект и сохранит токен — дальше он переиспользуется.

### 3. Перезапустить сессию Claude Code

**Обязательно.** Список MCP-инструментов формируется при старте сессии, поэтому
уже запущенная сессия сервер не увидит.

### 4. Проверить

```bash
claude mcp get ahrefs
```

Должно быть:

```
Status: ✔ Connected
```

Всё, готово — инструменты Ahrefs появятся в сессии.

---

## Две ловушки, на которых легко застрять

**`/mcp` внутри чата пишет «No MCP servers are configured», хотя сервер только
что добавлен.** Это не ошибка: сессия прочитала конфиг при старте, когда сервера
ещё не было. Лечится перезапуском. То же самое произойдёт и после шага 2 — если
авторизоваться, не перезапустив сессию, инструменты не появятся, даже когда
`claude mcp get` уже показывает `Connected`. Проще сделать шаги 1 и 2 подряд, а
перезапуститься один раз в конце.

**В расширении VSCode интерактивное меню `/mcp` может не отрисоваться** — вместо
него появится строчка «Use /mcp in the terminal for details», и авторизоваться
оттуда не получится. Поэтому в инструкции и стоит `claude mcp login`: она делает
то же самое из обычного терминала и от интерактивного меню не зависит.

## Если что-то пошло не так

Состояние всех серверов:

```bash
claude mcp list
```

`! Needs authentication` — значит не прошёл шаг 2, повторите
`claude mcp login ahrefs`.

Проверить, жив ли эндпоинт:

```bash
curl -s -o /dev/null -w "%{http_code}\n" -X POST \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"probe","version":"1"}}}' \
  https://api.ahrefs.com/mcp/mcp
```

**`401` — это нормальный и правильный ответ:** сервер жив и требует авторизации.
Значит проблема не в нём.

Сбросить авторизацию и пройти заново:

```bash
claude mcp logout ahrefs
claude mcp login ahrefs
```

Удалить сервер совсем:

```bash
claude mcp remove ahrefs -s local
```

## Полезно знать при работе

**Режим выборки решает всё.** В Ahrefs у любой цели есть режимы: домен без
поддоменов, домен с поддоменами, папка, точный URL. Если у проекта есть живые
поддомены, отчёт «с поддоменами» усреднит их с основным доменом, и понять
динамику конкретного хоста будет нельзя. Режим стоит задавать явно в запросе к
Claude, а не полагаться на умолчание.

**Домены-редиректы выглядят как пустые.** Если цель отдаёт `301` на другой домен,
Ahrefs покажет по ней почти нули — данные лежат на конечном домене. Перед
массовым прогоном имеет смысл прогнать список `curl -sIL` и заменить редиректы их
целями, иначе часть строк вернётся нулевыми и это будет выглядеть как реальный
результат.

**Batch Analysis экономит юниты.** До 200 целей за один вызов — заметно дешевле,
чем опрашивать домены по одному.
