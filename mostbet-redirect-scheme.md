# Mostbet: схема редиректов и доменная конструкция

Дата: 2026-08-11. Замеры с двух точек: **US-IP** (это окружение) и **RS-IP, Сербия**
(локальный агент). Расхождения между ними — не шум, а сама суть механики.

---

## 1. Коротко: что происходит

Пользователь заходит на `mostbet.com`. Сервер отдаёт **пустой SPA-шелл** (9.5 KB, ни
строчки контента). Скрипт в шелле спрашивает у сервера «куда этого юзера отправить»,
сервер отвечает JSON'ом с именем домена, и скрипт **меняет `window.location.href`** —
браузер уходит на региональное зеркало.

HTTP-редиректов (301/302/307) в этой схеме **нет вообще ни одного**. Именно поэтому
их не видно ни в curl, ни в панели DevTools как отдельную строку 30X.

---

## 2. Цепочка по шагам

```
GET https://mostbet.com/
    → 200, text/html, 9 580 B          # пустой SPA-шелл, <div id="root"></div>

    XHR: GET https://mostbet.com/api/v3/common/redirect
        → 200 {"redirect":true,"domain":"8unx689.com"}     (с RS-IP)
        → 204 пусто                                        (с US-IP)

    JS: window.location.href = "https://8unx689.com/"       # ← сам переход

GET https://8unx689.com/
    → 200, ~262 KB после гидрации   (с RS-IP)
    → 451 Unavailable For Legal Reasons, 5 308 B  (с US-IP)
```

Число HTTP-редиректов на всём пути: **0** (`num_redirects=0`, длина цепочки
`redirectedFrom()` равна 1).

---

## 3. Код, который это делает

Файл: `spa-static/1.4.2021/static/js/2199.b8225da8.chunk.js`, строка 3379.
Chrome через CDP подтверждает причину навигации: `reason=scriptInitiated`.

```js
const $2 = new Set(["mostbet.com", "mostkaei.com"]);   // ← гейт по ТОЧНОМУ имени хоста

function J2() {
    ...
    if (..., $2.has(window.location.hostname)) {
        const Ce = yield W2();              // GET /api/v3/common/redirect
        if (Ce != null && Ce.redirect) {
            const je = new URL(window.location.href);
            je.hostname = Ce.domain;        // подменяется ТОЛЬКО хост; path и query сохраняются
            window.location.href = je.href;  // ← переход
            return;
        }
    }
    // иначе — обычный рендер SPA в #root
}
```

Два важных следствия из этого кода:

**а) Переход сделан через `window.location.href = ...`, а не `location.replace()`.**
Проверено перехватом: `location.replace`, `location.assign`, `history.pushState`,
`history.replaceState`, `window.open` — **0 вызовов**, при этом переход состоялся.

**б) Гейт сравнивает хост на точное совпадение.** `guidebook.mostbet.com` не равен
`mostbet.com`, поэтому **поддомен под редирект не попадает** — и это ключ ко всей
конструкции (см. раздел 5).

---

## 4. Почему «кнопка Назад не работает»

Изначальная гипотеза была: `location.replace()` не оставляет записи в истории.
**Гипотеза опровергнута замером.**

```
history.length = 3
document.referrer = "https://mostbet.com/"

--- нажимаем BACK ---
сразу после back:  https://mostbet.com/     ← вернулись, запись в истории ЕСТЬ
через 12 секунд:   https://8unx689.com/     ← выбросило обратно
```

Реальная причина: возврат **срабатывает**, но `mostbet.com` при этом
перезагружается, SPA заново выполняет `J2()`, заново дёргает
`/api/v3/common/redirect`, снова получает `{"redirect":true}` и снова уводит на
зеркало. В логе на этом шаге виден повторный запрос к API.

Это **ловушка повторного редиректа**, а не подавление записи в истории. bfcache не
спасает: переход междоменный, страница переисполняется с нуля.

## 5. Доменная конструкция: три слоя

Это не один сайт, а три слоя с разными задачами.

| слой | домен(ы) | что отдаёт | robots.txt | роль |
|---|---|---|---|---|
| **контентный** | `guidebook.mostbet.com` | 180 KB готового HTML, WordPress | обычный WP (`Disallow: /wp-admin` и т.п.) | **держит индекс в Google** |
| **диспетчер** | `mostbet.com`, `mostkaei.com` | пустой шелл 9.5 KB + API редиректа | `Allow: /` | распределяет юзеров по зеркалам |
| **зеркала** | `8unx689.com`, … | рабочий сайт для юзеров | `Disallow: /` (с RS-IP) | доступ в обход блокировок |
| **отдельно** | `mostbett.bet` | 475 KB рабочий сайт | `Allow: *` + sitemap | цель `x-default` в hreflang |

### Причём здесь guidebook

`guidebook.mostbet.com` — это то, что **реально стоит в выдаче Google**. Проверка
поиска: из 8 результатов по бренду 7 — это страницы guidebook (`/log-in/`,
`/registration/`, `/download-app/`, `/mostbet-pakistan/`, `/monopolylive/` …).

Он не редиректится, потому что гейт из раздела 3 сравнивает хост на точное
совпадение, а `guidebook.mostbet.com` в списке `["mostbet.com","mostkaei.com"]`
отсутствует. Проверено прямо: в HTML guidebook строки `mostkaei` нет вообще
(0 совпадений), то есть скрипт-диспетчер туда не подключается.

При этом у guidebook разметка в порядке — есть `canonical`
(`https://guidebook.mostbet.com/`), есть hreflang на 13 языков
(ar, az, cs, de, en, es, fr, hu, it, pl, pt, ru, uz).

Итого разделение труда: **guidebook собирает трафик из поиска, апекс уводит
юзеров на зеркало.** Апекс в индексе тоже есть, но держится там только на
`<title>` и meta description — больше в его 9.5 KB ничего и нет.

## 6. Гео: где принимается решение

**На сервере (эдж), не в браузере.** Клиент только исполняет готовый ответ.

```
GET https://mostbet.com/api/v3/common/redirect
server-timing: country;desc="RS"
cache-control: no-cache, private
vary: Accept-Encoding, Accept-Language

{"redirect":true,"domain":"8unx689.com"}
```

Доказательство, что домен приходит с сервера, а не выбирается на клиенте: строки
`8unx689` в исходном HTML **нет вообще** (grep: 0 совпадений). Она появляется
только в ответе API.

Клиентские сигналы на выбор домена не влияют: `navigator.language` = `en-US`, а
домен выдан по IP (RS). Таймзона считывается, но лишь пишется в куку постфактум
(`set-cookie: tz=Europe%2FBelgrade`) — это следствие, а не вход. Geolocation API
не запрашивается вообще.

## 7. Разница по клиентам

Замеры с RS-IP:

| клиент | статус | размер тела | финальный URL |
|---|---|---|---|
| curl, без UA | 200 | 9 580 B | mostbet.com |
| curl, Chrome UA | 200 | 9 580 B | mostbet.com |
| curl, Googlebot UA | 200 | 9 580 B | mostbet.com |
| Chrome, JS **вкл** | 200 | 262 513 B | **8unx689.com** |
| Chrome, JS **выкл** | 200 | 9 573 B | mostbet.com |
| Googlebot UA, JS вкл | 200 | 127 988 B | **8unx689.com** |
| Googlebot UA, JS выкл | 200 | 9 573 B | mostbet.com |

Три curl-ответа **побайтово идентичны** (sha `f48ac73d58be` у всех трёх).

Вывод: **клоакинга по User-Agent нет.** Googlebot-UA получает ровно то же, что
обычный Chrome. Единственная переменная, меняющая исход, — исполняется JS или нет.

## 8. США: закрытый рынок, блокировка на эдже

С US-IP блокируется вообще всё, включая сам API:

| URL | ответ с US-IP |
|---|---|
| `https://mostbet.com/` | **204**, тело 0 байт |
| `https://mostbet.com/api/v3/common/redirect` | **204**, тело 0 байт |
| `https://8unx689.com/` | **451** Unavailable For Legal Reasons |
| `https://8unx689.com/robots.txt` | **451** (отдаётся HTML-заглушка вместо robots) |

Заголовок в ответе апекса: `server-timing: country;desc="US"`.

`451` — это код «недоступно по юридическим причинам», и зеркало отдаёт его явно.
Это прямо подтверждает версию: США — закрытый для оператора рынок, блокировка
стоит на эдже. Апекс при этом выбран более мягкий вариант — `204` вместо `451`,
то есть «пустой ответ» вместо явной ошибки.

Практическое следствие: **с US-IP редирект физически не может произойти** — API
отдаёт пустоту, `Ce` получается пустым, условие `Ce != null && Ce.redirect` не
выполняется, переход не делается. Отсюда и исходный симптом «через curl не пашет».

## 9. Оценка по требованиям Google

**Клоакинг — не подтверждается.** Контент по User-Agent не различается, хеши
одинаковые (раздел 7).

**JS-редирект сам по себе допустим.** Google исполняет JS и трактует
JS-редирект аналогично 301. Гео-редирект тоже легитимен, Google его прямо
допускает — но при условии, что все локализованные версии доступны по прямым
ссылкам и связаны корректным hreflang.

**Что действительно сломано:**

1. **`canonical` отсутствует полностью** — и на апексе, и на зеркале
   (0 совпадений). У guidebook он при этом есть.
2. **hreflang не согласован с фактом.** На апексе заявлен 21 альтернат
   (tr-TR, pt-PT, az-AZ, pt-BR, en-PK, cz-CZ, pl-PL, uk-UA, uz-UZ, ky-KG, en-IN,
   en-BD, el-GR, fr-MA, ne-NP, it-IT, de-DE, kk-KZ, by-BY, hu-HU, x-default).
   Фактического адресата редиректа `8unx689.com` в списке **нет**. Записи для RS,
   куда по факту отправили, тоже **нет**.
3. **`x-default` ведёт на `mostbett.bet`**, а не на сам апекс. Это отдельный
   рабочий домен (475 KB, `Allow: *`, свой sitemap, canonical на себя, hreflang
   отсутствует).
4. **Зеркало закрыто от сканирования** — `Disallow: /` (с RS-IP). При этом ни
   `canonical`, ни `meta robots`, ни `X-Robots-Tag` на нём нет.
5. **Апекс без JS не содержит индексируемого текста** — только `<title>`, meta
   description, прелоадер, пустой `<div id="root">` и
   `<noscript>You need to enable JavaScript to run this app.</noscript>`.

**Важная оговорка про пункт 4.** `Disallow: /` на зеркале, скорее всего, —
не ошибка, а намерение. Домены вида `8unx689.com` одноразовые: их задача —
пережить блокировку у провайдера, а не ранжироваться. Пускать их в индекс
означало бы растащить ссылочный вес по мусорным доменам. По той же причине их нет
и в hreflang. То есть конструкция **осознанная**, а не собранная по незнанию.

Общий вывод: это не «нарушение» в смысле спам-политик Google, а архитектура,
которая сознательно жертвует SEO-качеством апекса ради устойчивости к
блокировкам, и переносит всю индексируемую нагрузку на `guidebook.mostbet.com`.
Цена жертвы: самый сильный URL всего проекта держит нулевой контент, канонизации
нет, а hreflang описывает конструкцию, которой по факту не существует.

## 10. Что осталось непроверенным

- **Меняется ли выдаваемый домен от страны к стране.** Проверен ровно один регион
  (RS → `8unx689.com`). Механика (`{"redirect":..,"domain":..}` с сервера) это
  прямо предполагает, но замеров из других стран нет.
- **`mostkaei.com`** — второй домен в гейте. С US-IP не резолвится
  (`CONNECT tunnel failed, 502`), содержимое неизвестно. Что это — живой
  резервный диспетчер или остаток от прошлой схемы — не установлено.
- **Верификация Googlebot по обратному DNS.** Подменялся только User-Agent, что
  не доказывает, как система повела бы себя с настоящим IP Googlebot.
- **Ранжирование guidebook по коммерческим запросам.** Известно только, что он
  занимает выдачу по брендовым. Работает ли схема как источник небрендового
  трафика — не проверено.
