# Брейншторм: как вытащить позиции Mostbet обратно

Файл существует потому, что Agent Teams включается только при старте сессии.
После рестарта прошлая переписка не наследуется — вся вводная здесь.

**Перед обсуждением прочитать `CLAUDE.md`, затем `mostbet-redirect-scheme.md`.**

---

## 1. Что произошло

На `mostbet.com` выкатили урезанную версию — по требованиям комплаенса. Логика
была такая: посетитель из страны, где компания не работает, должен видеть
максимально безобидную страницу. Версию вырезали до состояния, где **текста
практически нет**.

Побочный эффект, которого не ждали: у главного домена **обнулились все серьёзные
SEO-показатели**. URL посыпались из индекса и продолжают сыпаться.

Домены, куда уходит редирект, — **временные, часто меняются**. Парадокс в том,
что именно на них лежит **старая версия сайта, где контент есть**. При этом
базовые вещи не соблюдены нигде: канонизации нет, hreflang не отражает реальность.

**Цель обсуждения: вернуть позиции.**

## 2. Что уже предлагалось

**Вариант A. Поднять жирные региональные домены как полноценные региональные версии.**
У проекта осталось несколько десятков таких. Сделать их индексируемыми, чтобы они
стояли в индексе и забирали региональную выдачу.

**Вариант B. Переклейка через 301.**
Взять все URL старой карты `mostbet.com` и поставить с них 301 на новый
консолидирующий домен (условно `mostbet.x`). На этом домене уже развесить hreflang
на все региональные зеркала, куда `mostbet.com` сейчас редиректит автоматом.

> Оговорка автора идеи: он не уверен, что на `mostbet.com` вообще остались
> страницы — есть ощущение, что уцелела одна главная, а вся старая карта
> рассыпалась. **Это надо проверить замером, а не принимать на веру.**

**Вариант C. Тот же hreflang, но не на зеркала, а на свои малостраничники.**
У команды есть сайты по 4–8 страниц (максимум 11–12) — статьи и обзоры, закрывающие
основные коммерческие интенты и суб-интенты: регистрация, приложение, `mostbet pc`,
`mostbet iphone`, бонусы и т.д. Команда уже работала по этой схеме и конкурировала
именно такими статейниками.

**Вариант D. Трогать сам JS-редирект.**
Отдельная и, возможно, самая тяжёлая часть. Технически всё то же самое делается на
стороне бэкенда, без перекладывания логики на браузер юзера. Команда, которая это
выкатила, — не SEO-специалисты.

## 3. Три сценария, под которые надо проектировать

Решение зависит от того, что согласуют. Нужны схемы под каждый исход, а не одна
идеальная:

1. **Ничего не меняется.** Ни редирект на зеркала не трогают, ни переклейку 301 не
   разрешают. Что вообще можно сделать в этих рамках?
2. **Средний.** Разрешают переклеить 301 потерянные страницы на другой сайт, а
   дальше с ним работать (варианты A / B / C). Редирект остаётся как есть.
3. **Полный.** Убеждаем, что чинить надо и то, и другое. Ресурсы на это есть.
   Проектируем обе части.

Основная часть — **301-переклейка**. Часть с JS-редиректом тоже критична: есть
подозрение, что фактически происходит клоакинг (см. п. 5 — по замерам это не
подтверждается, но вопрос надо закрыть аккуратно).

## 4. Вопрос, который надо закрыть по документации

Утверждение, требующее проверки **по документации Google, а не по SEO-блогам**:

> Редиректы на региональные версии делать можно (301 или 302). Но при этом на
> основной версии должны быть hreflang, ведущие на все зеркала. Тогда бот,
> заходящий из страны, откуда редиректа нет, видит hreflang и обходит все версии.

Что здесь надо установить точно:
- 301 или 302 для гео-редиректов — что рекомендует Google и почему;
- достаточно ли hreflang на нередиректящей версии, чтобы все локали были обойдены;
- как это сочетается с тем, что бот **не исполняет редирект, потому что тот на JS**.

Не принимать на веру ни выводы модели, ни выдачу Perplexity — там могла попасться
устаревшая информация. Ссылка на первоисточник обязательна.

## 5. Что уже установлено замерами — учитывать, не переоткрывать

- **Клоакинга по User-Agent нет.** Googlebot-UA и обычный Chrome получают
  побайтово идентичный ответ (совпадают хеши). Единственная переменная —
  исполняется JS или нет. По определению Google клоакинг — это разный контент
  **для юзеров и для поисковика** с целью манипуляции; различия по гео под это
  не подпадают и штатно поддерживаются (locale-adaptive crawling).
- **Апекс без JS не содержит индексируемого текста** — только `<title>`,
  description и пустой `<div id="root">`.
- **`canonical` на апексе отсутствует полностью.**
- **hreflang описывает несуществующую конструкцию:** 21 альтернат, реальных
  адресатов редиректа среди них нет, `x-default` уводит на `mostbett.bet`
  (посторонний домен, всего 6 URL в sitemap).
- **Закрыты от сканирования только одноразовые зеркала.** `guidebook.mostbet.com`,
  `mostbett.bet`, `mostbet.bet` — открыты.
- **США закрыты на эдже:** апекс и его API отдают `204`, зеркало — `451`.

## 6. Ответы владельца проекта — жёсткие рамки задачи

Это не пожелания, а ограничения. Схема, которая их нарушает, нежизнеспособна.

| вопрос | ответ |
|---|---|
| Контент на `mostbet.com` | **Нельзя вообще, ни для кого.** Не «для чужих гео» — ни для кого. |
| `mostbet.com` как вход для юзеров | **Должен остаться входом.** Убрать редирект нельзя. |
| «Жирные региональные домены» | Свои SEO-сайты, живут **месяцами и дольше**, с проставленными ссылками, заточены под конкретное гео и язык. **Не зеркала.** Пример: `mostbet-pl.com`. |
| Выгрузка старой карты URL | **Нет.** |
| Доступ к `mostbet.com` | Только через другую команду, по заявке. Но мы — основная SEO-команда. |
| Рынки | Сейчас немного (6–8 стран). Проектировать надо и под 6–8, и под масштаб до 50. |
| `mostbett.bet` | Наш. |
| `mostbet.bet` (одна «t») | Принадлежность неизвестна, судя по контенту — скорее всего чужой. |

### Что из этого следует (и должно быть отправной точкой спора)

**Апекс не может ранжироваться. Никогда, в рамках этих ограничений.** Значит,
попытки «вернуть контент на главную» бессмысленно даже обсуждать. Единственная
SEO-роль, которая ему остаётся, — **узел передачи сигналов**: разметка и ссылки,
а не текст.

Отсюда ключевая зацепка: **`hreflang` и `canonical` — это разметка в `<head>`, а
не контент.** Запрет комплаенса касается того, что видит пользователь. Аннотации
в `<head>` пользователю не видны, юрисдикционного риска не несут и при этом
решают ровно ту задачу, которая сейчас сломана. Это самый дешёвый и самый
согласуемый шаг из всех возможных — проверить эту трактовку с комплаенсом
следует в первую очередь.

**Второе следствие: индексируемый слой — это региональные сайты.** Они уже
существуют, уже с возрастом и ссылками, уже под гео и язык. Их не надо создавать,
их надо **связать**.

### Замер `mostbet-pl.com` (пример регионального сайта)

| параметр | значение |
|---|---|
| ответ | `200`, 166 KB, редиректов 0 |
| движок | WordPress |
| `<title>` | `Mostbet PL: 3000 PLN + 250 FS ⭐ Kasyno i Zakłady 2026` |
| `canonical` | есть, на себя |
| `meta robots` | `follow, index, max-snippet:-1, max-image-preview:large` |
| текста | ~970 слов |
| редирект-гейт | **отсутствует** |
| **`hreflang`** | **нет ни одного** |

Последняя строка — и есть главная дыра. Региональные сайты живут **изолированными
островами**: они не связаны ни между собой, ни с апексом. `hreflang` требует
**взаимных** ссылок — каждая версия должна подтверждать остальные. Значит работа
двусторонняя: разметка нужна и на апексе, и на каждом региональном сайте.

### Про отсутствующую карту URL

Ответ «нет» не закрывает вопрос, а переводит его в задачу. Старые URL
восстанавливаются: Search Console (запросом к другой команде), Wayback Machine,
исторические выгрузки Ahrefs/Semrush, профиль внешних ссылок (по ним видно, куда
раньше вели), внутренние ссылки с `guidebook`. Без списка **301-переклейку
спланировать нельзя**, поэтому восстановление карты — отдельная задача, а не
предусловие, которое можно пропустить.

## 7. Состав команды для обсуждения

4–5 тиммейтов с намеренно конфликтующими интересами, чтобы спор был настоящий:

| роль | за что топит | с кем конфликтует |
|---|---|---|
| **SEO-архитектор** | вернуть контент на апекс, канонизация, честный hreflang | с антиблоком |
| **Инфраструктурщик-антиблок** | живучесть под блокировками, ротация доменов | с SEO по всем пунктам |
| **Продуктовый / UX** | скорость входа, не показывать юзеру пустой экран | с обоими |
| **Риск и комплаенс** | закрытые рынки и юрисдикции — почему урезанная версия вообще появилась | с продуктовым |
| **Адвокат дьявола** | оспаривать консенсус, ловить места, где догадку приняли за факт | со всеми |

Задача — спорить между собой напрямую и опровергать версии друг друга, а не
отчитываться лиду по очереди. На выходе — **несколько схем под каждый из трёх
сценариев согласования**, с честными плюсами, минусами и ценой внедрения.
